# 仿真系统

两套系统是刻意做成异构的：一个服务端渲染、iframe、表格布局；一个 SPA、组件库、异步校验。这样 agent 不能靠"熟悉某一类页面"蒙混过关。

真实企业的 OA / 财务系统无法获取，这里自建的仿真系统只承载一个目的：**把真实环境里让人难受的那些细节复现出来**。

## 一、OA 系统（源）

**技术设定**：服务端渲染（Jinja2 模板 + 原生 HTML），无前端框架，`table` 布局。老系统的典型形态。

### 页面

| 路由 | 内容 | Agent 要做什么 |
|---|---|---|
| `GET /login` | 用户名 / 密码，失败三次锁 60 秒 | 登录，处理锁定态 |
| `GET /todo?page=1` | 待办表格，10 条/页 | 翻页找到目标单号 |
| `GET /doc/{doc_no}` | 单据头 + `<iframe>` 明细 | 读单号、部门、事由、合计、状态 |
| `GET /doc/{doc_no}/detail` | iframe 内：明细表 + 附件区 | 读明细行、附件张数与文件名 |
| `GET /attachment/{aid}` | 发票图片 | 视觉核对（可选） |

### 刻意设置的难点

- **无 `data-testid`、无 `aria-label`**，只能靠文本和结构定位
- 明细表是 `<table>`，列顺序：序号 / 发生日期 / 费用说明 / 金额 / 附件数
- 金额渲染成 `￥1,286.00元`——带货币符号、千分位、中文后缀
- 附件缩略图只有 `<img title="出租车发票.pdf">`，**hover 才出 tooltip**
- 单据头是 `<dl>`，字段名和值混在相邻 `<td>` 里，没有 `label`
- 分页是裸 `<a href="?page=2">`
- **会话 30 分钟过期**，过期后重定向到 `/login?redirect=/doc/...`（长任务跑到一半会掉线）

## 二、财务系统（目标）

> 完整规格（数据模型、API 契约、错误码、种子数据、实施顺序）见 [03-finance.md](03-finance.md)。这里只记录它在两个系统对照中的角色。

**技术设定**：SPA（React + 组件库），前端路由，异步校验。

### 页面

| 路由 | 内容 |
|---|---|
| `/login` | 登录，token 存 localStorage |
| `/vouchers` | 凭证列表 + "新建凭证"按钮 |
| `/vouchers/new` | 凭证录入表单 |
| `/vouchers/{no}` | 凭证详情（提交成功后跳转） |

### 录入表单结构

- **表头**：凭证日期、附单据数、摘要、制单人
- **明细行**（可增删）：科目（三级联动）、成本中心（依赖表头部门）、借方金额、摘要
- **保存链路**：点保存 → 服务端校验（800ms）→ 错误回填或"校验通过"
- **提交**：只有 `checker` 角色能看到按钮，`maker` 调用返回 403

### 刻意设置的难点

1. **科目三级联动**：选完一级才加载二级，有 300ms 延迟，选太快会拿不到选项
2. **成本中心依赖部门**：部门一改，整个下拉重载，已选值被清空
3. **异步校验**：点提交后按钮 `disabled` 且文案变"提交中..."，失败时表单顶部出现错误列表并高亮字段
4. **成功 toast 只显示 2 秒**，随后跳转——靠 toast 判断成败很容易踩空
5. **金额输入框**（v3）带千分位格式化，输入时自动补逗号

## 三、漂移模式（自愈测试的关键）

两个系统都支持 `?ui=v1|v2|v3`（或环境变量 `UI_VERSION`），**同一份业务数据渲染出不同的 DOM**。不用改代码就能复现页面改版，自愈率才测得出来。

| 版本 | 变更 | 针对的能力 |
|---|---|---|
| v1 | 基线实现 | — |
| v2 | OA 明细表列顺序调整；财务"提交"改成"保存并提交"；成本中心从 `select` 改成 `input` + 联想 | 语义定位、文案漂移 |
| v3 | OA 明细按 2 行分页（`?p=2`）；财务科目选项标签反转（`6601.03 交通费` → `交通费（6601.03）`）；金额输入带千分位 | 结构变化 + 标签解析 + 输入掩码 |

**一条硬约束**：漂移只改 UI，不改业务数据。否则核验无法区分"页面变了"和"数字真的变了"——那样测出来的自愈率没有意义。

## 四、共享的业务数据模型

两套系统各自持有，但字段语义对齐：

| 实体 | 字段 |
|---|---|
| 单据（OA） | 单号、申请人、部门、事由、合计金额、状态、明细行 |
| 明细行（OA） | 序号、发生日期、费用说明、金额、附件数 |
| 凭证（财务） | 凭证号、日期、附单据数、明细行、合计 |
| 凭证明细行（财务） | 科目编码、成本中心、借方金额、摘要 |
| 映射表 | 部门 → 成本中心；费用说明 → 科目 |

映射表是**业务规则**，不是 UI 的一部分。T5 会故意让它缺一条，用来测"agent 会不会瞎猜"。

## 五、两套系统怎么跑起来

- 各自独立进程、独立 SQLite 文件（`oa.db` / `fin.db`）。它们是"外部系统"的仿真，不与 Waybill 主库共用任何东西
- 全栈跑起来之后再补 Docker Compose
- 都提供 `/health` 和一个**只读的核对接口**（`/api/state/{doc_no}`），给评测 checker 用——注意这是 checker 的旁路，agent 不走它

**OA 已实现**：`python systems/oa/run.py`，详见 [systems/oa/README.md](../systems/oa/README.md)。财务系统待做。

接线时的两个坑，先记下来：

- 会话 TTL 用环境变量 `OA_SESSION_TTL` 调小，才能稳定复现"长任务跑到一半掉线"
- `/api/state` 在 v1/v2/v3 下返回完全一致的内容，这是 checklist 里判断"漂移只改 UI"的硬约束
